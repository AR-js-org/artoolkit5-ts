**Title:** feat: barcode / matrix-code marker support

## Summary

Add barcode (matrix code) markers alongside pattern markers. Verified feasible with **no new C++ work**: `setPatternDetectionMode`, `setMatrixCodeType`, and `getMatrixCodeType` are all present in `artoolkit5.wasm`, and `@ar-js-org/artoolkit5-wasm` already exports the constants `AR_MATRIX_CODE_DETECTION: 2` and `BARCODE_MARKER: 1`.

Unlike pattern markers, barcode markers need no `.patt` file — the ID is read directly from the marker geometry.

## Proposal

```ts
export function loadBarcodeMarker(
  state: ARToolKitState,
  barcodeId: number,
  markerWidth?: number
): number;
```

Registers the barcode ID in `state.markers` with `type: 'barcode'`. Requires the detector to be in a matrix-capable mode (see #06).

`MarkerPose` and `TrackedMarkerState` gain `type: 'pattern' | 'barcode'` so consumers can distinguish detections that share an integer ID space.

## Depends on

#06 — `configureDetector` supplies `detectionMode` and `matrixCodeType`.

## Risk: simultaneous pattern + barcode

ARToolKit5's C enum defines `AR_TEMPLATE_MATCHING_COLOR_AND_MATRIX: 3` and `AR_TEMPLATE_MATCHING_MONO_AND_MATRIX: 4`, which allow both marker families at once. Neither is generated by `artoolkit5-constants`, so `'color+matrix'` and `'mono+matrix'` will pass raw ints and are **unverified**.

Verify against the real engine. If they misbehave, document them as unsupported and require a single mode — the string-union API absorbs that without a breaking change.
